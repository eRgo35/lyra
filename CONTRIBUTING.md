# Contributing to Lyra

Thanks for your interest in Lyra! Bug reports, feature ideas and pull requests are welcome.

## Before you start

- Check existing [issues](https://github.com/eRgo35/lyra/issues) first, or open one to discuss larger changes.
- Security problems go through [SECURITY.md](SECURITY.md), not public issues.
- The development branch is **`senpai`**; open pull requests against it.

## Setup

You need a recent stable Rust toolchain (with `rustfmt` and `clippy`), a C compiler, `cmake`
and `pkg-config`. To actually run the bot you also need
[`yt-dlp`](https://github.com/yt-dlp/yt-dlp) and a Discord bot token; see the
[README](README.md#quick-start). With Nix, `nix develop` provides the build dependencies.

## Checks

CI (`.github/workflows/ci.yml`) runs the following on every push and pull request to `senpai`.
Run them locally before you push:

```bash
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo build --locked
cargo test --locked
```

Use `cargo fmt` to fix formatting. Please add or update unit tests for logic that can be tested
without a Discord connection.

## Changelog

User-visible changes (features, fixes, behaviour or dependency changes, docs worth noting) must be
recorded in [CHANGELOG.md](CHANGELOG.md) under the section for the version in progress, following the
[Keep a Changelog](https://keepachangelog.com/en/1.0.0/) format.

## Commits and pull requests

- Use [Conventional Commits](https://www.conventionalcommits.org/) style messages, for example
  `fix(music): handle empty queue` or `docs: clarify configuration`.
- Keep pull requests focused and describe what changed and why.
- Do not edit `.github/workflows/release.yml` by hand: it is generated by cargo-dist.

## Releases

Maintainers cut releases by hand; see [RELEASING.md](RELEASING.md).
