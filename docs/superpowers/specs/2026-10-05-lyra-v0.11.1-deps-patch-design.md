# Lyra v0.11.1 — Dependabot Patch Release

- **Date:** 2026-10-05
- **Status:** Draft, awaiting user review
- **Target version:** 0.11.1 (patch release on the 0.11.x line)
- **Branch:** `senpai`

## Problem

After the v0.11.0 release, GitHub Dependabot shows 6 open alerts on the
default branch:

| # | Sev | Pkg | Summary | Reachable in our build? |
|---|---|---|---|---|
| 31 | **high** | rustls-webpki | DoS via panic on malformed CRL BIT STRING | yes — via reqwest 0.11 → hyper-rustls 0.24 → rustls 0.21 → webpki 0.101 |
| 21 | medium | rustls-webpki | faulty CRL matching | yes — same path |
| 10 | medium | ring | AES panic on overflow | **no** — 0.16.20 is in lockfile but not built by any target |
| 24 | low | rustls-webpki | name constraints for wildcard | yes — same path |
| 23 | low | rustls-webpki | name constraints for URI names | yes — same path |
| 25 | low | rand | unsound with custom logger using `rand::rng()` | yes — rand 0.7.3 pulled in by owoify 0.1.5 |

The 17 "fixed" alerts auto-closed when v0.11.0 brought in newer versions;
the 6 remaining open ones persist because the **transitive dep graph** still
contains vulnerable side-paths:

- `reqwest 0.11.27` (pinned by songbird 0.4.6) → `rustls 0.21.12` /
  `rustls 0.22.4` → `rustls-webpki 0.101.7` / `0.102.8` (vulnerable).
- `owoify 0.1.5` (latest published version, frozen) → `rand 0.7.0` → 0.7.3
  (vulnerable).
- `ring 0.16.20` is in the lockfile but `cargo tree` reports "nothing to
  print" for any built target — stale lockfile entry from a now-removed
  optional feature.

## Goal

Cut a v0.11.1 patch release on `senpai` that closes 5 of the 6 open
Dependabot alerts (the four rustls-webpki + the rand 0.7.3 low). The
remaining ring 0.16.20 alert is a stale lockfile entry that resolves
itself once the dep graph changes.

## Approach

### Step 1: Replace owoify with an inline implementation (closes alert #25)

`owoify 0.1.5` is a ~200-line single-file crate that does regex-based
text replacement and picks a random emote face. The `OwOifiable` trait
has one method: `owoify(&self) -> Self` (taking a `String`, returning a
new `String`).

Replace the dep with an inline implementation in
`src/commands/tools/owoify.rs`. Use `rand 0.10` (already in the tree).

The inline implementation:

- Keep the same trait name (`OwOifiable`) so the call site
  `text.owoify()` doesn't change.
- Keep the same face list as the upstream crate.
- Use the same regex set as the upstream crate.

Acceptable risk: minor textual differences vs upstream owoify. The
command's documented UX ("owoifies whatever you want uwu") is preserved.

### Step 2: Bump songbird 0.4.6 → 0.6 (closes alerts #31, #21, #24, #23)

songbird 0.6 requires `reqwest ^0.12.2`. This forces the whole chain
up:

```
songbird 0.6 → reqwest 0.12.x → rustls 0.23 → rustls-webpki 0.103.x
```

The 0.103 line of `rustls-webpki` contains the patched versions for all
four open alerts (#31, #21, #24, #23). Once songbird 0.6 lands, those
alerts auto-close.

songbird 0.6 reorganizes features compared to 0.4:

- `default = ["driver", "gateway", "rustls", "serenity", "tungstenite"]`
  (no more split into multiple features).
- `rustls` feature replaces the old `rustls-tls` selector.
- `builtin-queue` may or may not be present (verify).
- `serenity` feature for the `SerenityInit` shim.

The actual API surface (`Call`, `Songbird::manager`, `TrackHandle`) is
mostly the same between 0.4 and 0.6, with breaking renames in:

- `Call::join` is replaced by `Songbird::join(guild_id, channel_id)`.
- The `YoutubeDl::new_ytdl_like` helper from `songbird::input` may have
  changed signature.
- `songbird::driver::Config` and related have been reshuffled.

This is the same `songbird 0.4 → 0.6` migration the v0.11.0 spec listed
under Phase 1 as a deferred escalation. We are now doing it.

### Step 3: Drop openssl-replacement flag (no change from v0.11.0)

`reqwest` already on `rustls-tls` from v0.11.0. No further change.

### Step 4: Bump Cargo.toml version 0.11.0 → 0.11.1

Patch bump per semver: security fixes only, no API change.

## Files Touched

- `Cargo.toml` — drop `owoify`; bump `songbird` to 0.6; bump `reqwest`
  to 0.12; version `0.11.0` → `0.11.1`.
- `Cargo.lock` — regenerated by cargo.
- `src/commands/tools/owoify.rs` — inline owoify implementation.
- `src/commands/music/play.rs` — adapt to songbird 0.6 API
  (`Songbird::join` instead of `Call::join`; verify `YoutubeDl` shape).
- `src/commands/music/soundboard/effect.rs` and `stream.rs` — verify
  they still compile; minor adjustments if they touch `Call::join` or
  `TrackHandle`.
- `src/main.rs` — `register_songbird` signature likely unchanged.
- `CHANGELOG.md` — add `[0.11.1] - 2026-10-05` entry with the security
  fix notes.

## Files Explicitly Not Touched

- `flake.nix`, `flake.lock`.
- `.github/workflows/*`.
- `scripts/*`.
- `assets/*`, `LICENSE.md`.
- All other commands (only `owoify`, `play`, and `soundboard/*` are
  expected to need source edits).

## Risks

- **songbird 0.6 API renames**: `Call::join` → `Songbird::join`,
  `YoutubeDl::new_ytdl_like` may have shifted. Likely affects 3-5 lines
  in `play.rs` and the two soundboard files.
- **owoify regex divergence**: the inline implementation may produce
  slightly different ouput than the upstream crate. User-visible
  difference is minor (different emote face distribution or different
  replacement order) and unlikely to be noticed in practice.
- **Build-env workarounds unchanged**: still need
  `CMAKE_POLICY_VERSION_MINIMUM=3.5` + `LIBRARY_PATH=/tmp/opuslib`. The
  new audiopus_sys that songbird 0.6 pulls in may have a different
  CMake version requirement.
- **Dependabot alert #10 (ring 0.16.20) may not auto-close**: the
  version is still in the lockfile until something prunes it. If
  cargo's new resolver doesn't prune it, we'll need a follow-up to
  clean the lockfile. Acceptable: alert #10 is medium severity but
  **not reachable in any built target**.
