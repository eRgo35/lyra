# Lyra v0.11.0 — Make It Build Again + Maintenance

- **Date:** 2026-10-05
- **Status:** Draft, awaiting user review
- **Target version:** 0.11.0 (next minor release per semver)
- **Branch:** `senpai` (work directly on the active branch)

## Problem

Lyra v0.10.8 does not build on a fresh checkout in October 2026:

1. `songbird` is pinned to a now-404 Git fork (`https://github.com/eRgo35/songbird`).
   The author has presumably deleted or renamed their fork, so `cargo build` fails
   at dependency resolution.
2. Major libraries are 1–2 versions behind the latest published crates:
   - `songbird` 0.4.6 → 0.6.0
   - `poise` 0.6.1 → 0.7.0
   - `reqwest` 0.11.27 → 0.13.5
   - `rand` 0.8.5 → 0.10.3
   - `tokio` 1.39.2 → 1.53.2
   - `tracing-subscriber` 0.3.18 → latest
   - `symphonia` 0.5.4 → latest
3. Two debug leftovers in `src/main.rs`:
   - A hard-coded blocked user ID `123456789` in the global `command_check`.
   - A hard-coded guild ID `512680330495524873` for slash-command registration.
4. `.env.example` documents only `DISCORD_TOKEN` + `PREFIX`; the hard-coded guild
   ID is not configurable.
5. `.env.example` + `README.md` are not updated for the new env var.
6. Possibly unused dependencies (`json`, `owoify`, `tracing-futures`,
   `spotify-parser`, `once_cell`) — to be audited.

## Goal

Cut a v0.11.0 release on the `senpai` branch that:

- Builds and runs against current `crates.io` with no git-fork dependencies.
- Uses the latest published versions of every library in `Cargo.toml` (the
  "latest of everything" upgrade scope).
- Keeps the public command list, slash registration behavior, prefix behavior,
  audio stack, and embed style unchanged.
- Removes the debug user-block.
- Makes the registration guild ID configurable via `GUILD_ID`.
- Drops any library that is not actually used.
- Updates `.env.example` and `README.md` to match.

## Non-Goals

- No new user-facing commands or features in this minor release.
- No restructuring of module layout beyond what API changes force.
- No automated test suite introduction (out of scope for this release; smoke
  test only).
- No CI / `cargo-dist` / release-plz changes (those are owned by the existing
  CI workflow and were last touched in 2024).
- No `nix` overlay updates.
- No new documentation pages (only inline edits to existing README sections).

## Approach — Three Ordered Phases

The library upgrades are correlated breaking changes (poise 0.7 requires a
newer serenity, which uses reqwest 0.13, which uses a new rand, etc.).
A single "big bang" cut is possible but harder to bisect. Three ordered
phases keep each commit independently reviewable and end with a green build
between phases.

### Phase 1 — Build-only: kill the dead songbird fork

- Replace
  ```toml
  songbird = { version = "0.4.6", default-features = true, features = ["builtin-queue"], git = "https://github.com/eRgo35/songbird" }
  ```
  with the crates.io equivalent at the highest 0.4.x that compiles cleanly
  against the rest of the lockfile. The author's fork was based on songbird
  0.4.6, so `songbird = "0.4"` (resolving to 0.4.7, the latest 0.4.x) is the
  first attempt. If that fails to compile against poise 0.6.1 / serenity 0.12,
  escalate to 0.5.x; if 0.5.x also fails, escalate to 0.6.x. Each escalation
  forces the corresponding API fixes to be moved into Phase 1.
- Audit and drop any obviously unused crate from `[dependencies]`:
  - `json` — almost certainly unused (replaced by `serde_json`).
  - `owoify` — verify it is used by `tools::owoify`; otherwise drop.
  - `tracing-futures` — verify it is used; otherwise drop.
  - `spotify-parser` — verify it is used; otherwise drop.
  - `once_cell` — verify it is used; otherwise drop.
- No source-code changes expected in this phase; songbird 0.4.x is what the
  codebase targets.

Acceptance:
- `cargo build --release` succeeds.
- No `[patch.crates-io]` table needed; remove `serenity-voice-model` patch if
  no longer relevant.

### Phase 2 — Poise 0.7 / Serenity 0.12.5+

- Bump `poise = "0.6.1"` → `poise = "0.7.0"`.
- Bump `serenity = "0.12"` → `serenity = "0.12.5"` (or latest 0.12.x
  compatible with poise 0.7).
- Fix every compile error in `src/main.rs` and every `src/commands/**/*.rs`
  file. Expected changes:
  - `#[poise::command(...)]` attribute surface.
  - `poise::PrefixFrameworkOptions` field renames (e.g. `additional_prefixes`,
    `edit_tracker`).
  - `poise::Context::author()` / `cache()` etc. — possibly new types.
  - `register_in_guild` / `register_globally` parameter order.
  - `ActivityData::listening` — likely unchanged.

Acceptance:
- `cargo build --release` succeeds.
- All 30 command files compile.
- No change to the on-disk public API (slash command list, alias behavior,
  prefix behavior).

### Phase 3 — reqwest 0.13 / rand 0.10 / tokio / tracing / symphonia + the four UX items

Library bumps:
- `reqwest` 0.11 → 0.13.
- `rand` 0.8 → 0.10.
- `tokio` 1.39 → 1.53+.
- `tracing` + `tracing-subscriber` to latest.
- `tracing-futures` removed if `tracing-subscriber` and `tracing` cover the
  use case.
- `symphonia` 0.5 → latest.
- `openssl` — drop the vendored openssl if `rustls_backend` (already enabled
  on serenity) is enough. Verify `cargo build --release` succeeds without
  `openssl` before removing.

UX items:
1. **Remove hard-coded user-block.** Delete the `command_check` block in
   `src/main.rs` that compares against `123456789`. No replacement; self-hosters
   do not inherit someone else's block.
2. **Make `GUILD_ID` configurable.** Read
   `std::env::var("GUILD_ID").ok().and_then(|s| s.parse::<u64>().ok())`. If
   `Some(id)`, call `register_in_guild(ctx, &commands, id.into())`. If `None`,
   call `register_globally(ctx, &framework.options().commands)`.
3. **Update `.env.example`.** Add a `GUILD_ID=` line (commented-out, with
   explanation that it scopes slash registration to one guild; if unset,
   commands are registered globally and may take up to an hour to propagate).
4. **Update `README.md`.** Add `GUILD_ID` to the "Getting started" section
   with the same explanation. No other README edits.

Acceptance:
- `cargo build --release` succeeds.
- `cargo clippy --release -- -D warnings` passes (best-effort; warnings
  pre-existing in code we don't touch are not blockers).
- `cargo run` launches, prints "connected successfully!", and exits cleanly
  via Ctrl-C.
- If a Discord token is available, slash commands register against the
  configured guild (or globally when unset).
- README + `.env.example` updated.

## Files Touched

- `Cargo.lock` — regenerated by cargo.
- `src/main.rs` — `command_check` removal, `GUILD_ID` env reading, register

- `src/commands/**/*.rs` — dep-driven API fixes across phases 2 and 3 only.
- `.env.example` — add `GUILD_ID` line.
- `README.md` — add `GUILD_ID` note in "Getting started".

## Files Explicitly Not Touched

- `flake.nix`, `flake.lock`.
- `.github/workflows/*`.
- `scripts/cross-build.sh`, `scripts/launch.sh`.
- `assets/*`.
- `LICENSE.md`.

## Risks

- **songbird API drift** between 0.4 → 0.5/0.6: `Call::join`, event trait
  surface, `TrackHandle::stop`, queue helpers. Mitigation: end each phase
  with a green build.
- **poise 0.7 attribute surface**: many small breakage (e.g. `channel=`,
  `rename`, `discard_spare_arguments`, `ephemeral`). Mitigation: in-place
  fix during Phase 2.
- **rand 0.10**: `gen_range`, `thread_rng` signatures. Mitigation: trivial
  find/replace per call site.
- **reqwest 0.13**: `Client::new()` is unchanged; `Response::json::<T>()`
  signature is similar; `.error_for_status()` exists. Low risk.
- **Vendored openssl removal**: requires `rustls_backend` feature on serenity
  (already enabled). Verify build env still produces binaries that can talk
  to TLS endpoints.
- **Hard-coded guild ID change**: behavior differs subtly between
  `register_in_guild` (instant) and `register_globally` (up to 1h). This is
  documented in `.env.example` + README.

## Verification (per phase)

End of each phase:
1. `cargo build --release` succeeds with exit code 0.
2. `cargo tree --depth 1` shows the expected new versions.
3. No new `#[patch.crates-io]` entries remain unless still required.

End of Phase 3 (final, pre-release):
1. `cargo build --release` succeeds.
2. Bot launches with a stub `.env` (token from real or test account) and
   reaches the "connected successfully!" log line.
3. Bot registers slash commands (guild-scoped when `GUILD_ID` set, global
   otherwise).
4. Bot exits cleanly via Ctrl-C.
