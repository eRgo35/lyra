# Lyra v0.11.2 — CI Repair + Loose Ends Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every GitHub workflow green or removed, close/document the open Dependabot alerts, and fix the robustness gaps found in the 2026-10-20 review.

**Architecture:** Workflow fixes first (unblocks releases), then quality gates, then dependency/TLS cleanup, then runtime hardening, then docs. Each task ends in a commit on `senpai`. Nothing is pushed until the user says so.

**Tech Stack:** Rust 2021, poise 0.7, serenity 0.12.5, songbird 0.6, cargo-dist, GitHub Actions.

**Spec:** Review findings in this session (no separate design doc). Prior context: `docs/superpowers/specs/2026-10-05-lyra-v0.11.1-deps-patch-design.md`.

## Global Constraints

- Branch: `senpai`; commit per task; do NOT push or move/delete existing tags or remote branches.
- Do not touch the public command list or prefix/slash behaviour.
- Verification baseline: `cargo build --locked`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked` all pass after every task.
- Secrets (`RELEASE_PLZ_TOKEN`) cannot be created by the agent.

## Execution notes (deviations from the plan above)

- **Task 4:** none of the three dependency items could be fixed in this repo; recorded as known/unresolved in `CHANGELOG.md` `[0.11.2]`.
  - `libcrux-chacha20poly1305 0.0.8`: `cargo update --precise` refused, `hpke-rs-libcrux 0.6.1` pins `libcrux-aead ^0.0.7` (via davey → songbird 0.6.0). Crate is not compiled for any target.
  - `rustls-webpki 0.102.8`: serenity 0.12.5 (last 0.12 release) → tokio-tungstenite 0.21. Needs serenity `next`.
  - `native-tls`: only `spotify-parser 1.0.1` (own crate, `eRgo35/spotify-parser`) enables reqwest default features. Needs a 1.0.2 release.
- **Task 5:** also made the process exit 1 when `client.start()` fails (found by the smoke run: a bad token left the process hanging until Ctrl-C).
- **Task 6:** used poise's `guild_only` attribute on the 15 commands that call `ctx.guild_id().unwrap()` instead of a helper. `embed()`/`error_embed()` always return `Ok`, so their `.await.unwrap()` cannot panic and were left alone.
- **Task 7:** `posix` has no pure function to test (inline `SystemTime`), so only `owoify` got tests. The `repeat` NonMax wrap was not covered.
