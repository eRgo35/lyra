# Lyra v0.11.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut a v0.11.0 release of the lyra Discord music bot that builds
cleanly against current `crates.io` (no git-fork dependencies) using the
latest published releases of every library, drops unused dependencies, removes the
hard-coded user-block, makes the slash-registration guild ID configurable
via `GUILD_ID`, and updates `.env.example` and `README.md` accordingly.

**Architecture:** Three sequential phases, each producing a working release
binary before the next starts:

1. **Phase 1** — kill the dead songbird git fork by switching to crates.io,
   drop unused deps (`json`, `tracing-futures`); minimum-diff.
2. **Phase 2** — bump poise 0.6 → 0.7 and serenity to the latest 0.12.x
   compatible with poise 0.7; fix every command file's API surface.
3. **Phase 3** — bump reqwest 0.11 → 0.13, rand 0.8 → 0.10, tokio to latest,
   tracing + tracing-subscriber to latest, drop vendored openssl in favor of
   rustls-tls; plus the four UX/hygiene items.

**Tech Stack:** Rust 2021 edition, poise 0.7.x, serenity 0.12.x, songbird
0.6.x (crates.io), reqwest 0.13.x, rand 0.10.x, tokio 1.x.

## Global Constraints

These constraints apply to every task. Every requirement below is copied
verbatim from `docs/superpowers/specs/2026-10-05-lyra-v0.11-design.md`.

- `songbird` must come from `crates.io`, not a git fork. After Phase 1,
  the `Cargo.toml` entry for `songbird` MUST NOT contain a `git = ` key.
- The `[patch.crates-io]` table MUST be removed if no other patch is needed.
- The hard-coded `123456789` user-block in `src/main.rs` MUST be deleted.
- The hard-coded guild ID `512680330495524873` in `src/main.rs` MUST be
  replaced with reading `GUILD_ID` from the environment; unset → global
  register; set → guild register.
- `.env.example` MUST document the `GUILD_ID` variable.
- `README.md` "Getting started" section MUST mention `GUILD_ID`.
- `Cargo.toml` MUST list only libraries that are used by the project source.
  Concretely: `json` and `tracing-futures` MUST be removed.
- The vendored `openssl` feature MUST be removed in favor of `rustls-tls`,
  since `serenity` already enables `rustls_backend`.
- Final acceptance: `cargo build --release` succeeds; `cargo run` reaches
  the "connected successfully!" log line and exits cleanly via Ctrl-C.
- Branch: `senpai` (the only active branch). Do not create a worktree.
- No new public-facing features in this release.

## Audit Results (pre-flight, do not re-audit in tasks)

- `json`: NOT used in source. Drop.
- `tracing-futures`: NOT used in source. Drop.
- `owoify`: USED by `src/commands/tools/owoify.rs`. Keep.
- `spotify-parser`: USED by `src/commands/music/play.rs`. Keep.
- `once_cell`: USED by `src/commands/tools/uptime.rs`. Keep.
- `regex`: USED by `src/commands/music/play.rs`. Keep.
- `rand`: USED by `src/commands/tools/ai.rs` and `src/commands/tools/dice.rs`
  via `rand::thread_rng()` and `Rng::gen_range()`. Keep, but the call sites
  will likely need updates when bumping to 0.10 (`Rng::random_range` replaces
  `gen_range` in 0.10).
- `openssl`: only required as a transitive for `reqwest`'s `default-tls` /
  `native-tls` features. Drop it once reqwest is configured for `rustls-tls`
  only.
- `symphonia`: not directly used in source. Currently declared so songbird's
  input can decode audio formats. After bumping songbird to 0.6, check
  whether the upstream songbird 0.6 still requires the explicit
  `symphonia` feature declaration in the consumer's `Cargo.toml`. If not,
  drop it; if yes, update its version.

Replace with:

```rust
        .setup(move |ctx, ready, framework| {
            Box::pin(async move {
                info!(
                    "{} [{}] connected successfully!",
                    ready.user.name, ready.user.id
                );
                ctx.set_activity(Some(ActivityData::listening(prefix + "help")));

                let commands = &framework.options().commands;
                if let Some(guild_id) = std::env::var("GUILD_ID")
                    .ok()
                    .and_then(|s| s.parse::<u64>().ok())
                {
                    poise::builtins::register_in_guild(ctx, commands, guild_id.into()).await?;
                } else {
                    poise::builtins::register_globally(ctx, commands).await?;
                }

                Ok(Data {
                    http_client: HttpClient::new(),
                })
            })
        })
```
